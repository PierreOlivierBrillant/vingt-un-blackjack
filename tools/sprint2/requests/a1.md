## Décisions prises (A1)

- **Interface `GameModule`** (`src/games/kernel/module.ts`, en-tête = mode d'emploi pour la phase B) : les 14
  méthodes du plan (`limits, init, openRound, act, onDeadline, validateBets, closeBetting, seatClear, onLeaving,
  bot, power, rank, stats, fairEstimate`) + `game`, `available`, `money` ('board' | 'stack'), `actionSchema`
  (zod strict des actions du jeu), `seatInit`, `legalActions` (bots + tests de propriétés) et des options
  (`canStart`, `onSitOut/onSitIn`, `botBuyInCents`, `countsForAffinity`, `onClose`). Un module déclare ses types
  avec `defineGameModule<P, S, V, A>({…})`. Il agit uniquement via `ctx` (phase/échéance, tour, événements,
  `settle`, `idle`, `secret`, `removeSeat`, marchés) : aucune API de débit n'existe dans `ctx`.
- **Argent** : seuls `join` (cave), `setBets` (voie rapide) et un `act` qui renvoie `debitCents` débitent ; tout ce
  que le noyau lance lui-même (échéances, ouverture de coup, bots) est enveloppé dans `auto()` qui LÈVE si un débit
  est tenté. Au règlement d'un jeu à tapis, le noyau vérifie : report ≤ tapis, `staked` = tapis − report, une ligne
  pour tout argent qui quitte le tapis, `net = return − staked` (un module fautif fait échouer la transaction).
- **Stubs** : `available: false` → `gameJoin` refusé (FEATURE_UNAVAILABLE), pas de table simulée, une table encore
  ouverte se ferme à sa prochaine transaction en remboursant tout (tapis verrouillés compris, caves, file).
- **Voie rapide setBets** : lit table + `bets/{uid}` + wallet (+ inventaire si pouvoir) et n'écrit que
  `bets/{uid}` + wallet (+ inventaire) ; refusée après l'échéance + DECISION_GRACE_MS (BAD_PHASE) sans avancer la
  table (le client appelle `gamePoke`). La fermeture relit chaque `bets/{uid}` des sièges par lecture directe
  (aussi des documents absents : une création concurrente invalide la transaction).
- Pas de fin anticipée des mises quand tous les humains ont misé (impossible sans écrire la table).
- Un pouvoir posé sur un tapis est consommé tout de suite et reste attaché au coup (non remboursé si on vide le tapis).
- `gameLeave` accepte aussi une table blackjack ; `gameJoin{joinCode}` rejoint un code de n'importe quel jeu.
- Correctif blackjack au passage : un siège « leaving » retiré plus tard n'efface plus le `currentTableId` (sinon un
  joueur parti en cours de main puis assis ailleurs pouvait s'asseoir à une troisième table).
- Marchés : paiement sauté quand `humanTradeCount === 0` (aucune position possible) ; `tradeShares` l'incrémente.
- Tests d'intégration des callables du noyau exécutés EN PROCESSUS (`test/integration/inproc.ts` :
  `execute()` réel sur l'émulateur Firestore) avec coin/duel substitués, car l'émulateur Functions charge le
  registre de production (stubs). Les tests HTTP couvrent le comportement des stubs.
- `test/integration/account.test.ts` : l'attente d'`equipCardStyle` inclut maintenant `title: null` (régression
  de A0, qui n'avait pas relancé l'intégration).
- `vitest.integration.config.mts` : séquenceur alphabétique (z_sim, qui sème la base, en dernier) au lieu de
  « le plus long / en échec d'abord » de vitest, qui pouvait lancer z_sim en premier.
