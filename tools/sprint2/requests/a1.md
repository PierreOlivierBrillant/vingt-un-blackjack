## Pour la session principale / les autres chantiers (hors de mon périmètre, rien modifié)

- `firebase/functions/eslint.config.mjs` : ajouter `src/games/kernel/**` (et `src/games/*/engine*.ts`) à la règle
  `no-restricted-imports` qui garde `src/engine/**` pur (le noyau n'importe rien de Firebase aujourd'hui, par convention).
  Attention : `kernel/tx.ts` est la colle Firestore du noyau ; la règle doit viser `machine.ts`, `module.ts`, `bets.ts`,
  `rank.ts`, `effects.ts`, `unavailable.ts`, pas `tx.ts`.
- Rendez-vous (implémenteur romance) : `users/{uid}/romance/{personnage}` peut exister avec SEULEMENT
  `tablePlay: { [jour]: n }` (incrément aveugle écrit par chaque règlement de table, blackjack compris) avant le
  premier `romance{op}` : compléter les autres champs de `RomanceDoc` par défaut à la lecture.
- Flutter (A2) : `GameBetDoc.bets` est TOUJOURS ce qui est sur le tapis maintenant (mises reportées du craps
  comprises) ; `round` = dernier coup où ce tapis a changé. Après un règlement : `bets` = report (vide sauf craps),
  `previous` = tapis joué (bouton « Rejouer »).
- Flutter (A2) : un code privé d'un jeu du noyau se rejoint par `gameJoin{mode:'joinCode'}` (qui accepte aussi les
  codes blackjack et répond `game`) ; `joinMatchmaking{joinCode}` avec un code non-blackjack répond `WRONG_GAME`.
- `tools/start_classroom.ps1` (réservé) : le nombre de tables simulées par jeu se règle par la variable
  d'environnement `SIM_GAME_TABLES` (0..8, défaut 2) ou `tools/sim_runner.ps1 -GameTablesPerGame N`.
