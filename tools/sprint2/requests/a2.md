# Demandes du chantier A2 (Flutter) au contrat / au backend

Rien n'a été modifié côté `firebase/**` : ces points sont contournés côté Dart en attendant.

## 1. Index Firestore pour le salon (A1, `firestore.indexes.json`)
Le salon liste les tables publiques d'un jeu avec
`gameTables where game == <jeu> && status == 'open' && isPrivate == false orderBy updatedAtMs desc limit 50`
(`app/lib/data/firebase/firebase_game_repository.dart`, `watchLiveTables`). L'émulateur n'exige pas
d'index composite, mais une vraie base le ferait : ajouter
`gameTables : game ASC, status ASC, isPrivate ASC, updatedAtMs DESC`.

## 2. `gameJoin` en mode `joinCode` sur une table de hold'em
Le contrat exige `buyInCents` pour le hold'em, mais en `joinCode` le client ne connaît pas le jeu
avant la réponse. Contournement Dart : si le jeu choisi dans le salon est le hold'em, l'app demande
la cave avant d'envoyer le code (`app/lib/features/games/game_join.dart`). Un code de hold'em tapé
avec un autre jeu sélectionné échouera donc (BUY_IN_OUT_OF_RANGE). Proposition : en `joinCode` sans
`buyInCents` sur une table de hold'em, asseoir avec la cave minimale, ou renvoyer une raison dédiée
(`BUY_IN_REQUIRED`) avec les limites dans `details`.

## 3. Rejoindre une table publique précise (spectateur → joueur)
`gameJoin` n'a que `quick | createPrivate | joinCode` (comme `joinMatchmaking`). Le bouton
« Jouer à ce jeu » du spectateur fait donc un `quick` au même palier (peut asseoir ailleurs).
Proposition (facultative) : un mode `table` avec `tableId`.

## 4. Parité testable de constantes non exportées dans `contract.json`
Le client reflète en dur `GAME_PHASES`, `GAME_TIMING`, `GAME_MISSED_ROUNDS_LIMIT`, `GAME_EVENTS_CAP`
(`app/lib/domain/game_table.dart`, classe `GameTiming`) et `GAME_RANK_POINTS`. Les ajouter à
`test/golden/contract.json` (test `contract.test.ts`) permettrait de les vérifier dans
`app/test/unit/contract_parity_test.dart`.

## 5. Marchés des jeux du noyau : `handNumber` = tour
Le client affiche « tour n° N » pour un marché d'un jeu du noyau quand `handNumber` est renseigné
(`marketSubtitle`), et « série » (pas de numéro) sinon : c'est conforme au commentaire de
`MARKET_KINDS` (types.ts). Aucun changement demandé, simple confirmation de lecture.
